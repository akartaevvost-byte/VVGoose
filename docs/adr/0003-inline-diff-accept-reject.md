# ADR 0003: Встроенное сравнение изменений кода агента с принятием и отклонением

## Статус
Принято (Accepted)

## Контекст
При взаимодействии с AI-агентом Goose агент часто предлагает модификации исходных файлов проекта (через вызовы инструментов редактирования и создания файлов).
В базовом интерфейсе чата результаты вызовов инструментов выводились в виде блоков текста внутри сообщений. Пользователю было сложно:
- Оценить масштаб изменений в контексте всего файла.
- Увидеть точные диффы (удалённые и добавленные строки) без внешних утилит.
- Интерактивно подтвердить или отклонить правку до её фиксации на диске.

## Решение
Принято решение реализовать встроенный механизм рецензирования изменений в стиле Cursor:

1. **Встроенное отображение (Inline Unified Diff)**:
   - При генерации изменений агентом через событие `AGENT_PROPOSE_DIFF` файл автоматически открывается в центральной панели редактора в режиме сравнения `DiffEditor` (`renderSideBySide: false`).
   - Удаляемые строки подсвечиваются мягким красным фоном, добавляемые строки — зелёным фоном.

2. **Баннер рецензирования (Diff Banner)**:
   - В верхней части редактора отображается плавающая панель с названием файла, статистикой изменений (`+X / -Y строк`), а также кнопками:
     - **Принять (Accept)**: горячая клавиша `⌘Enter` / `Ctrl+Enter`.
     - **Отклонить (Reject)**: горячая клавиша `⌘Backspace` / `Ctrl+Backspace` или `Escape`.

3. **Сквозная интеграция с ACP (Agent Client Protocol)**:
   - Если изменение было инициировано инструментом агента с запросом подтверждения прав (`toolApprovalData`), нажатие «Принять» вызывает `resolveAcpPermissionRequest(sessionId, toolId, generation, 'allow_once')` и сохраняет файл на диск.
   - Нажатие «Отклонить» передаёт в ACP `deny_once`, отклоняя операцию агента без изменения файла.

4. **Алгоритм подсчёта различий (LCS Line Diff)**:
   - Статистика изменений (`diffUtils.ts`) рассчитывается на базе алгоритма Longest Common Subsequence (наибольшая общая подпоследовательность) с оптимизацией отсечения общего префикса и суффикса. Это гарантирует корректный учёт перестановок, вставок и удалений строк без ложных нулевых значений.

## Обоснование (Rationale)
Рецензирование правок по месту их применения (in-situ review) — ключевой фактор эффективности в средах вроде Cursor:
- Разработчик видит окружающий контекст кода (функцию, класс, модуль), а не только изолированный кусок диффа.
- Исключается риск случайного перезаписывания важных пользовательских правок.
- Поддержка привычных горячих клавиш ускоряет процесс валидации работы агента в разы.

## Рассмотренные альтернативы
1. **Вывод диффа исключительно в ленте чата**:
   - *Минусы*: Ограниченная ширина окна чата делает длинные строки нечитаемыми, теряется контекст всего файла, сложнее пролистывать многострочные изменения.
2. **Автоматическое сохранение без предварительного показа**:
   - *Минусы*: Высокий риск повреждения кода при некорректной генерации AI, ухудшение доверия пользователя к агенту.
3. **Модальное диалоговое окно для каждого диффа**:
   - *Минусы*: Блокирует интерфейс приложения, не позволяет параллельно изучать другие файлы проекта.

## Последствия (Consequences)
### Положительные:
- Безопасный и контролируемый процесс применения AI-генерации.
- Полная синхронизация между UI-состоянием и ACP-протоколом разрешений.
- Высокая точность подсчёта статистики изменений.

### Компромиссы и риски:
- Необходимость обработки гонок состояния при одновременном редактировании файла пользователем и агентом (решено через функциональное чтение состояния `openFilesRef` и флаг `isDirty`).
