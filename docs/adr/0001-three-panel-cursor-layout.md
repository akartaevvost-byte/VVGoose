# ADR 0001: Трёхпанельный макет рабочего пространства в стиле Cursor

## Статус
Принято (Accepted)

## Контекст
Изначально настольное приложение Goose Desktop представляло собой монолитное диалоговое окно чата. Для изучения файловой структуры проекта, просмотра результатов работы агента и внесения правок пользователям приходилось постоянно переключаться между Goose и внешней средой разработки (VS Code, JetBrains, Cursor). Это приводило к постоянной потере контекста и снижало продуктивность совместной разработки с AI-агентом.

Возникла потребность трансформировать Goose Desktop в полноценное рабочее окружение (IDE), позволяющее обозревать структуру проекта, просматривать и редактировать код, а также интерактивно взаимодействовать с агентом в едином окне.

## Решение
Принято решение реализовать трёхпанельный макет рабочего пространства по образцу современных AI-ориентированных сред разработки (таких как Cursor):

1. **Левая панель (Проводник файлов / File Explorer)**:
   - Отображение дерева файлов с ленивой загрузкой подпапок.
   - Визуализация статусов Git (Modified, Untracked, Ignored) с агрегацией на уровне родительских папок.
   - Поддержка управления файлами: создание, удаление, переименование, перетаскивание (Drag & Drop) в чат.
   - Быстрое скрытие/раскрытие по комбинации `⌘B` / `Ctrl+B`.

2. **Центральная панель (Область редактора / Editor Area)**:
   - Вкладки открытых файлов с индикацией несохранённых правок (`isDirty`).
   - Полнофункциональный редактор кода с подсветкой синтаксиса и миникартой.
   - Строка состояния с текущей строкой, колонкой, кодировкой и языком.
   - Встроенный режим сравнения изменений (Diff Editor) для рецензирования предложений агента.

3. **Правая панель (Панель агента / Chat Panel)**:
   - Диалог с агентом Goose с сохранением всех существующих возможностей (инструменты, голосовой режим, расширения).
   - Интерактивный сплиттер (Resizable Splitter) между редактором и чатом с сохранением ширины в `localStorage` и защитой от схлопывания панелей.

## Обоснование (Rationale)
Трёхпанельная структура является признанным индустриальным стандартом для сред разработки:
- Пользователь видит структуру проекта, текущий код и диалог с ассистентом одновременно.
- Отпадает необходимость переключаться в сторонние редакторы для проверки простых правок.
- Агент может направлять пользователя к конкретным строкам кода и файлам, открывая их в центральной панели.

## Рассмотренные альтернативы
1. **Сохранение монолитного чата с модальными окнами для просмотра файлов**:
   - *Минусы*: Модальные окна блокируют интерфейс, невозможно одновременно смотреть на файл и формулировать инструкцию агенту.
2. **Двухпанельный макет (Редактор + Чат без проводника файлов)**:
   - *Минусы*: Требует ручного ввода путей или перетаскивания файлов из системного файлового менеджера (Finder / Explorer), отсутствует контекст структуры проекта.
3. **Разработка исключительно расширения для VS Code**:
   - *Минусы*: Goose Desktop развивается как независимое приложение без привязки к конкретным проприетарным платформам.

## Последствия (Consequences)
### Положительные:
- Пользовательский опыт приближен к лучшим современным решениям (Cursor / VS Code).
- Полная прозрачность работы агента: изменения видны мгновенно в контексте файлов проекта.
- Удобная навигация и контекстные действия над файлами (добавление в контекст чата, открытие).

### Компромиссы и риски:
- Увеличение сложности состояния интерфейса (решено централизованным `WorkspaceContext`).
- Необходимость строгой валидации путей IPC-запросов от рендерера для защиты от path traversal.
- Повышенные требования к производительности рендеринга дерева файлов (решено виртуализацией через `react-virtuoso`).
