# ADR 0002: Использование Monaco Editor для центральной Области редактора

## Статус
Принято (Accepted)

## Контекст
Для реализации центральной панели редактора в рамках трёхпанельного макета (ADR 0001) требовался движок текстового редактора кода, поддерживающий:
- Подсветку синтаксиса для широкого спектра языков программирования (Rust, TypeScript, Python, Go, Markdown, JSON, YAML и др.).
- Встроенный режим визуализации различий (Diff Editor) для рецензирования правок агента.
- Высокую производительность при просмотре и редактировании файлов среднего и крупного размера.
- Привычный для разработчиков набор горячих клавиш, миникарту, сворачивание блоков (code folding), нумерацию строк и темы оформления.

## Решение
В качестве движка редактора кода и сравнения файлов выбран **Monaco Editor** (через библиотеку `@monaco-editor/react`).

Реализована конфигурация:
- Настраиваемая тёмная тема `goose-dark`, гармонично интегрированная с дизайн-системой Goose.
- Система вкладок с поддержкой переключения, закрытия и горячих клавиш (включая `⌘S` / `Ctrl+S`).
- Мемоизированные статические опции редактора (`DIFF_EDITOR_OPTIONS` и `EDITOR_OPTIONS`) для предотвращения лишних перерисовок и переинициализаций Monaco.
- Лимит на размер открываемых файлов (до 10 МБ) с информативным уведомлением пользователя в случае превышения.

## Обоснование (Rationale)
Monaco Editor является базовым движком VS Code и Cursor. Его выбор обеспечивает:
1. **Идентичность пользовательского опыта**: разработчики не испытывают когнитивного трения при переходе между VS Code/Cursor и Goose Desktop.
2. **Готовый DiffEditor**: Monaco содержит встроенный зрелый компонент сравнения файлов как в параллельном (side-by-side), так и в объединённом (inline unified) режимах.
3. **Стабильность и производительность**: виртуализация строк и токенизация синтаксиса оптимизированы для современных браузерных и Electron-сред.

## Рассмотренные альтернативы
1. **CodeMirror 6**:
   - *Плюсы*: Меньший вес пакета, модульная архитектура.
   - *Минусы*: Реализация объединённого diff editor и интеграция темы потребовали бы создания значительного объёма сложного рукописного кода; токенизация многих редких языков требует подключения отдельных модулей.
2. **Ace Editor**:
   - *Минусы*: Устаревшая архитектура, слабая поддержка современных стандартов доступности и тем, уступает Monaco в эргономике diff-представления.
3. **Легковесный HTML `<textarea>` с подсветкой через Highlight.js / Prism.js**:
   - *Минусы*: Отсутствие синхронного редактирования с подсветкой, отсутствие виртуализации, невозможность реализации интерактивного diff editor.

## Последствия (Consequences)
### Положительные:
- Высокое качество отображения кода и подсветки синтаксиса из коробки.
- Плавный скроллинг, поддержка миникарты и сворачивания функций.
- Возможность бесшовного переключения между обычным редактированием и просмотром diff предложений агента.

### Компромиссы и риски:
- Monaco Editor увеличивает размер итогового бандла приложения на несколько мегабайт (для настольного Electron-приложения это приемлемый компромисс).
- Необходимость управления жизненным циклом инстансов Monaco во избежание утечек памяти при быстром переключении вкладок.
